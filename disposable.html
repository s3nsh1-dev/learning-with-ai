Stage 6 Practical Technical Glossary

  • EC2 — Elastic Compute Cloud: AWS virtual machines running an Ubuntu 24.04 LTS host to run our Docker container stack.
  • SG — Security Group: AWS hypervisor-level virtual firewall regulating inbound traffic (HTTP port 80, SSH port 22) and dropping unauthorized probes.
  • SSH — Secure Shell: Cryptographically secured protocol on TCP port 22 using private keys (.pem) to manage remote hosts.
  • GHCR — GitHub Container Registry: GitHub's private OCI registry (ghcr.io) hosting our SHA-tagged Docker images.
  • PAT — Personal Access Token: GitHub authentication secret scoped strictly to read:packages so EC2 can pull private images without repo write access.
  • CIDR — Classless Inter-Domain Routing: IP address range notation (e.g., 0.0.0.0/0 for public internet, IP/32 for a single host).
  • APT — Advanced Package Tool: Debian/Ubuntu package manager used to install Docker Engine from the official upstream repository.
  • chmod 400 — Owner Read-Only: Mandatory permission for private SSH keys; OpenSSH refuses connections if permissions are wider.
  • chmod 600 — Owner Read-Write: Secure permission for server.env and release.env so non-root processes cannot read database secrets.

Step 02 / Cloud Perimeter

AWS EC2 Launch & Security Group Hardening

We launch a single Ubuntu 24.04 LTS instance. We configure AWS Security Groups at the hypervisor level to enforce the principle of least network privilege.

Setting Recommended Value Why This Choice
AMI Ubuntu Server 24.04 LTS (HVM), SSD Volume Type Official modern Linux base, x86_64 architecture.
Instance Type t3.micro (or t2.micro) AWS Free Tier eligible, 1 vCPU, 1 GB RAM (sufficient for React Nginx + Express).
Key Pair todo-deploy-key.pem (RSA / OpenSSH) Provides key-only SSH access. Never allow password authentication.
Storage 16 GiB gp3 Provides ample space for Docker layers and cached images.

Action 1: Configure Security Group Ingress Rules

When launching the instance, create a new Security Group named todo-app-sg with these exact rules:

Type Protocol & Port Source Purpose
SSH TCP 22 My IP (e.g. 203.0.113.50/32) Restricts administrative shell access exclusively to your workstation.
HTTP TCP 80 0.0.0.0/0 (Anywhere IPv4) Allows public visitors to reach your Nginx reverse proxy.
CUSTOM TCP 5432 & 5000 BLOCKED (Do NOT add) Database & Express API remain isolated on the private Docker bridge network.

Action 2: Harden SSH Key Permissions Locally

OpenSSH requires that private key files are readable only by their owner. If permissions are too open (0644), OpenSSH will reject the key with WARNING: UNPROTECTED PRIVATE KEY FILE!.

Local Workstation Terminal 
# Move the downloaded key to your secure SSH folder
mkdir -p ~/.ssh
mv ~/Downloads/todo-deploy-key.pem ~/.ssh/

# Apply mandatory owner-read-only permissions (chmod 400)
chmod 400 ~/.ssh/todo-deploy-key.pem

# Connect to your newly launched instance
# (Replace <EC2_PUBLIC_IP> with your instance's IPv4 address from AWS Console)
ssh -i ~/.ssh/todo-deploy-key.pem ubuntu@<EC2_PUBLIC_IP>
✓ Connection Checkpoint

When prompted: Are you sure you want to continue connecting (yes/no/[fingerprint])? type yes. You are now inside your EC2 host terminal: ubuntu@ip-172-31-xx-xx:~$.

Step 03 / Host Runtime

Docker Engine Installation & Private Registry Login

Now that you are connected via SSH, provision the container engine. Do not run apt install docker.io — that installs Ubuntu's outdated snapshot lacking the Compose v2 CLI plugin. We install official Docker CE directly from Docker's upstream repository.

Action 1: Install Official Docker CE & Compose Plugin

Run this complete provisioning block inside the EC2 SSH session:

EC2 Host Terminal (Ubuntu 24.04 LTS) 
# 1. Update system package index and install prerequisite tools
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg

# 2. Add Docker's official GPG signing key
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# 3. Add official Docker repository to Apt sources
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 4. Install Docker Engine, CLI, Containerd, and Compose Plugin
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 5. Add 'ubuntu' user to docker group (enables non-root docker commands)
sudo usermod -aG docker ubuntu

# 6. Activate group permissions immediately in current shell
newgrp docker

# 7. Verify Docker works without sudo
docker version
docker compose version

Action 2: Authenticate with GHCR using --password-stdin

Log in to GitHub Container Registry using the Personal Access Token (PAT) you generated in Step 1.

⚠️ Security Warning: Never use -p <token>

Using -p $TOKEN reveals the credential to anyone running ps aux and logs it in ~/.bash_history. Always pipe the token into --password-stdin.

EC2 Host Terminal (Secure GHCR Login) 
# Replace YOUR_GITHUB_USERNAME with your GitHub handle (e.g. s3nsh1-dev)
# Replace ghp_xxxx with your PAT token
echo "ghp_YOUR_TOKEN_HERE" | docker login ghcr.io -u s3nsh1-dev --password-stdin

You should see the confirmation: Login Succeeded. Docker stores the authentication token in ~/.docker/config.json.

Action 3: Verify Image Pull from GHCR

Prove that your credentials can pull the private images published by CI:

EC2 Host Terminal 
# Pull both images using your release SHA tag (e.g. sha-b94f0e5)
docker pull ghcr.io/s3nsh1-dev/docker-beginner-simulation-client:sha-b94f0e5
docker pull ghcr.io/s3nsh1-dev/docker-beginner-simulation-server:sha-b94f0e5

# Verify images are stored on host disk
docker images
Step 04 / Configuration

Setting Up /opt/todo-app & File Permissions

In production, we maintain a dedicated root directory /opt/todo-app. It contains only three configuration files:

  1. docker-compose.prod.yml — Defines the multi-container topology.
  2. release.env — Declares the current immutable IMAGE_TAG.
  3. server.env — Contains the Neon PostgreSQL database URL and port.

Action 1: Create Host Directory

EC2 Host Terminal 
sudo mkdir -p /opt/todo-app
sudo chown -R ubuntu:ubuntu /opt/todo-app
cd /opt/todo-app

Action 2: Copy Deployment Files to EC2

You can transfer the files from your local workstation via scp, or create them directly in the EC2 terminal:

Option A: From Local Workstation via SCP 
# Run from inside docker-beginner-simulation on your local laptop:
scp -i ~/.ssh/todo-deploy-key.pem \
  docker-compose.prod.yml release.env server.env \
  ubuntu@<EC2_PUBLIC_IP>:/opt/todo-app/

Alternatively, create them directly on the EC2 host:

Option B: Directly on EC2 Host Terminal 
# 1. Create docker-compose.prod.yml
cat << 'EOF' > /opt/todo-app/docker-compose.prod.yml
services:
  client:
    image: ghcr.io/s3nsh1-dev/docker-beginner-simulation-client:${IMAGE_TAG}
    init: true
    restart: unless-stopped
    ports:
      - "80:80"
    depends_on:
      server:
        condition: service_healthy
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"

  server:
    image: ghcr.io/s3nsh1-dev/docker-beginner-simulation-server:${IMAGE_TAG}
    restart: unless-stopped
    expose:
      - "5000"
    env_file:
      - ./server.env
    healthcheck:
      test:
        [
          "CMD-SHELL",
          'node -e "fetch(''http://localhost:5000/api/health'').then(r => process.exit(r.ok ? 0 : 1)).catch(() => process.exit(1))"',
        ]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 15s
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"
EOF

# 2. Create release.env
cat << 'EOF' > /opt/todo-app/release.env
IMAGE_TAG=sha-b94f0e5
EOF

# 3. Create server.env (Neon PostgreSQL connection)
cat << 'EOF' > /opt/todo-app/server.env
DATABASE_URL=postgresql://neondb_owner:npg_XLH6srTOnD5J@ep-tiny-snow-b3xbjqhp-pooler.c-4.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
PORT=5000
EOF

Action 3: Restrict File Permissions (chmod 600)

server.env contains your production database credentials. Lock it down so other users and processes cannot read it:

EC2 Host Terminal 
chmod 600 /opt/todo-app/server.env
chmod 600 /opt/todo-app/release.env
ls -la /opt/todo-app

Action 4: Validate Configuration Dry-Run

Before launching, test that Docker Compose successfully resolves the environment variables without syntax errors:

EC2 Host Terminal 
cd /opt/todo-app
docker compose -f docker-compose.prod.yml --env-file release.env config

The output will display the fully rendered YAML specification with ${IMAGE_TAG} replaced by sha-b94f0e5.

Stack Startup & 4-Tier Smoke Test Verification

With the files in place, launch the containers in detached mode and execute the four verification tiers required to prove Stage 6 acceptance criteria.

EC2 Host Terminal
